# 性能

目标：整本 35 页 A4、双面，从「按下回车」到「最后一张出纸」。

## 三个瓶颈，逐个拆

### 1. gs 的分带渲染（4 倍）

gs 默认按 1 MB 条带渲染。含大图/渐变的页面，**每条带都要重跑一遍显示列表并重新解码图片**，
实测某复杂页 21.9 s/页。整页放内存后：

```bash
-dMaxBitmap=80000000 -dBufferSpace=80000000
```

同页降到 **5.5 s**。整页 1-bit 位图仅 4.35 MB，80 MB 足够放下整页加工作缓冲。

> 代价：重采样边界有极轻微差异，单页比对 57 像素 / 3487 万像素（0.00016%），散在几十条扫描线上，
> 肉眼不可见。

### 2. 串行编码（4 倍）

一次 gs 调用渲染多页（bundle）是单线程的，多核帮不上忙：**5.72 s/页**。
改成**一页一条独立 gs 流水线 + 线程池**：

| 并发 | 单页耗时 | 吞吐 |
|---|---|---|
| 1 | 5.55 s | 0.18 页/s |
| 4（4 核 ARM） | 1.65 s | **0.61 页/s** |

35 页编码总耗时 **518 s → 93.9 s**。滑动窗口只保留 `workers` 个任务在飞，中间文件不堆积；
结果按页序吐出，保证送给打印机的顺序正确。

### 3. 作业边界造成的停顿（观感）

早期每 4 页发一个独立作业：新 TCP 连接 + 完整 PJL 头 + `0x42` 流结束 + `FXJOBINFO` + `@PJL EOJ`。
每组结束打印机都要 flush / eject / 双面翻转器归位，于是纸与纸之间有顿挫。

改成**整本一个作业、单连接边编码边发送**：

```
建一次 TCP ─> PJL 头 ─> [第1页编码完立即写] ─> [第2页] ─> … ─> 0x42 + FXJOBINFO ─> close
```

- 首张纸延迟仍只有「前 workers 页编码完」的时间（约 6 s）
- 打印机视角是一个大作业，中途没有作业边界
- `sendall` 阻塞形成天然背压：打印机缓冲满 → 发送停 → 编码窗口不再往前推，中间文件不堆积

## 最终瓶颈是打印机引擎

| 环节 | 实测 |
|---|---|
| 编码吞吐（4 路并行） | 1.44 s/页 |
| 打印机引擎 | 4.3–5.3 s/**面**（双面交替：打印 3.5 s / 翻转+打印 5.2 s）|

按 4.4 s/面算，35 面 ≈ 155 s，加首组 12 s ≈ **整本 2.6–3 分钟**，约 13.6 页/分钟。
编码已比打印快 3 倍多，再提并发没有收益；降 dpi 也不改善总时长（引擎速度是物理上限）。

## 可调参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `HBPL_WORKERS` / `--jobs N` | `min(4, CPU 核数)` | 并行页数。超过物理核数只会争抢 |
| `HBPL_TMP` | `/dev/shm`（>200 MB 时） | 中间文件目录。每页约 8.7 MB，写内存盘避免磨 SD 卡 |
| `--group N` | 关闭（流式） | 退回「每 N 页一个作业」，用于排查 |
